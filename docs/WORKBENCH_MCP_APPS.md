# Walle Memory：多空间授权与条目编辑

本版把记忆浏览、更新动态、多 workspace 授权和日常使用说明放进 Walle Memory MCP。工作台使用现有 MCP OAuth 连接，不再依赖本机 skill、API Key 或钥匙串。已于 2026-10-11 部署到公网，详见 [公开变更与验证摘要](PUBLIC_CHANGE_SUMMARY.md)。实际宿主的工具刷新、界面展示和新增多空间授权仍需客户端验收。

## 界面

界面使用深蓝色，左侧边栏可收起；窄屏收起后隐藏导航，主区保留展开按钮。左侧选择当前 workspace，并在全部记忆、待办与进展、日程、个人与偏好、项目上下文、随手记录之间切换。中间按更新时间排列条目，支持搜索 key 和摘要、按状态筛选、分页加载；右侧按需读取正文、更新时间、到期时间和访问元数据。未知前缀的条目仍能在“全部记忆”中查看。

界面名称统一为 Walle Memory。顶部统计收为一条紧凑信息栏，让条目列表和详情获得更多空间；显示当前空间与查询范围的条目总数。已完成、待跟进、今天更新三个指标只统计已经加载的条目，界面明确标注此范围。状态从摘要中的明确前缀识别，不当作权威业务结论；“开发已完成，待验证”显示待验证，“送评分发已完成，结果待反馈”保留阶段完成及后续摘要。打开详情后可核对正文。

更新动态显示创建、更新和删除。数据库触发器覆盖原有 REST 与 MCP 写入；读取引起的访问计数变化不会形成更新事件。记录从迁移 0006 应用后开始，旧记忆仍显示原 updated_at，不生成虚构历史。动态保存 key、操作、摘要与时间，不保存历史正文。每次返回最近 60 条动态。

工作台默认每 45 秒在可见时刷新，也支持手动刷新。空间切换清除上一空间的详情，过期的异步响应不会覆盖最新选择。界面提供浏览和已有条目编辑。选中条目后点击编辑，可修改摘要、结构化字段或普通文本；其他字段折叠显示并完整保留。点击保存时通过 memory_update 更新服务器，再用 memory_get 重新读取确认，最后刷新索引和动态。新增和删除仍通过对话；界面不会直接执行待办。编辑期间暂停自动刷新，手动刷新保留草稿，切换空间或条目前提示处理未保存的修改。

工作台通过 `memory_workbench` 和 `ui://walle-memory/workbench-v1.html` 资源关联，并使用官方 `@modelcontextprotocol/ext-apps` SDK 经宿主调用 MCP 工具。资源是自包含 HTML，不直接连接 Walle HTTP API，也不接收用户 token。协议依据：[MCP Apps 官方文档](https://modelcontextprotocol.io/extensions/apps/overview)。

## 授权多个 workspace

OAuth 授权页明确勾选 1–100 个当前账户拥有的 workspace，再选择其中一个作为默认空间。请求中的每一个空间都在同一授权事务中验证归属；重复、空、超量、外部账户和未选择的默认空间均拒绝。没有空间会被自动授权。

`oauth_grant_spaces` 保存这一组权限范围。现有 `oauth_grants.space_id` 继续代表默认空间，迁移会把已有单空间授权原样写入关联表。旧连接和未传 workspace_id 的调用保持原来的目标。读取、写入、删除和 GC 都支持显式 workspace_id，但只能使用当前连接已授权且仍归当前账户的空间。

刷新令牌保留同一组空间，不扩大权限；新增 workspace 必须重新授权。撤销应用会撤销整组空间。当前默认空间删除或归属变化会使原连接整体失效；其他已授权空间归属变化后不再可访问。已连接应用页展示空间列表及默认空间。

OAuth 的读、写、删除、GC scope 对选中的整组空间一致。本版未增加逐空间不同 scope 或跨账户协作成员授权。

## 日常使用和 skill 对齐

| 用户场景 | MCP 行为 |
| --- | --- |
| 记住一件事、添加待办 | 用稳定 key 保存简明正文和摘要；只记录，不执行待办 |
| 做完了、更新进展、改截止时间 | 先读取原文，保留未要求修改的字段和原到期时间，再更新对应记忆 |
| 最近完成、没完成什么 | 先读取索引，按相关时间和 key 找记录，再按需读正文核对阶段完成与后续工作 |
| 找以前的记忆 | FTS5 搜索 key 和摘要，最多 20 条；不宣称搜索正文或进行语义检索 |
| 打开工作台、看看最近更新 | 调用 memory_workbench，宿主支持 MCP Apps 时展示交互界面 |
| 切换日常工作、个人或项目空间 | memory_workspaces 列出已授权目标，在后续调用显式传 workspace_id |
| 删除指定记忆 | 明确目标的删除按用户授权执行；模糊批量清理先确定范围 |
| 清理到期记录 | 只对指定已授权空间执行 GC，独立检查 gc scope |

这些规则已写入 MCP initialize instructions 和各工具 description，不需要额外本地 skill 才能发现。还包含北京时间解释、未指定时刻的保留、任务状态与下一步分开记录、检索内容不作为指令、错误时不自动重放写操作。

原本地 skill 的传输与凭据配置属于旧实现，不照搬内网地址、API Key 或 Keychain 前提。公网 MCP 当前已有 summary，因此也不照搬旧 skill 中“summary 未实现”的过时说明。

## 工具与文件

原有七个工具保持名称，并增加可选 workspace_id；原有输出结构保持兼容。新增：

- `memory_workspaces`：列出本连接已授权空间、默认空间、权限。
- `memory_workbench`：返回当前索引和动态，并关联 MCP App 资源。
- `memory_update`：修改已有有效条目的正文和摘要，要求 memory:write，保留 key 和精确 expires_at。expected_updated_at 与数据库当前版本不符时返回 conflict，已删除或过期时返回 missing_or_expired；不会新建、复活或自动重试。版本检查、更新和权限复核在同一 D1 事务内完成，更新时间单调递增。该工具允许界面调用，原有创建、删除和 GC 工具仍只向模型开放。只读连接隐藏编辑入口。

关键实现：`src/mcp.ts`、`src/memory-instructions.ts`、`src/oauth.ts`、`src/oauth-ui.ts`、`src/store.ts`、`apps/workbench/`，以及迁移 0005 和 0006。`src/workbench-html.ts` 是构建产物，由界面源码生成。

## 验证和上线

2026-10-11 本地验证：130 项测试全部通过，TypeScript 检查和 Worker dry-run 构建通过。隔离 D1 测试覆盖旧授权迁移、空间隔离、刷新与撤销、授权后归属变化及并发写入检查。浏览器通过官方 AppBridge → App → MCP Worker 链路验证搜索、状态过滤、更新动态、两个 workspace 之间切换、详情清空、390px 手机布局和授权页多选。编辑验收覆盖结构化字段和普通文本的保存与重新读取、原到期时间和未编辑字段保留、并发冲突阻断、未保存草稿的离开保护、刷新和失败时的草稿保留；无页面脚本错误。测试账户、令牌与数据库均为临时本地数据。这不是生产宿主验收，部署后仍需在实际 MCP Apps 宿主中检查展示和授权。

预览使用在线索引快照；预览 workspace、授权和变更动态均为本地测试数据；为保持界面简洁，不在页面顶部显示验收说明。预览不代表已在当前公网 MCP 中发布。

本次已获用户明确部署授权，生产数据库和 Worker 已更新。发布流程如下：

1. 重新核对当前 Worker 版本、部署配置、D1 绑定、迁移账本、现有 schema 和备份恢复点，确认源代码与当前线上版本不存在未合并差异。
2. 本次只应用 `0005_oauth_workspaces.sql` 和 `0006_memory_changes.sql`。此前生产 0001–0003 是手动初始化，账本从 0004 开始；不能重跑所有仓库迁移。
3. 核对旧授权的 workspace 关联只包含原单个空间，旧数据和权限不变，再部署候选 Worker。
4. 通过真实宿主重新发现工具，读取现有默认空间并打开工作台。用户再次 OAuth 授权时勾选多个 workspace，验证切换、刷新和撤销。
5. 以实际日常场景验收记住、更新、回顾、删除。确认 MCP 可独立承担这些能力后，再由用户移除本地 skill。

代码回滚可保留新增表和触发器。若回滚期间旧代码产生新 OAuth grant，再次前滚时需在同一部署流程中补齐这些 grant 的原单空间关联；不能把未授权空间补入旧 grant。不要通过整库恢复覆盖上线后的业务记录。

本地复现：在 `walle-memory-worker/` 安装根依赖，并在 `apps/workbench/` 安装界面依赖，然后运行 `npm test`。`node test/workbench-preview-server.mjs` 启动临时预览宿主；未提供本地索引快照时使用一条明确的示例记忆。

## 新会话与手机入口

部署并刷新插件工具后，在新会话选择或 @ Walle Memory，发送“打开 Walle Memory”，由 memory_workbench 返回界面；不依赖前一会话、本地 skill 或本机预览进程。该入口需要客户端加载插件并支持 MCP Apps，不能保证每个新会话自动打开。

已验证 390px 浏览器布局，但尚未验证手机 ChatGPT 客户端的实际呈现。当前版本没有独立的公网 /workbench 网页；/mcp 是协议接口，ui:// 是宿主资源标识，均不能作为手机网页直链。若需要手机浏览器直接打开，可在现有账号登录体系上增加 /workbench 网页入口，并添加到手机主屏幕。

参考：[OpenAI MCP UI 文档](https://developers.openai.com/plugins/build/chatgpt-ui)、[新会话调用示例](https://developers.openai.com/plugins/build/app-quickstart)。
